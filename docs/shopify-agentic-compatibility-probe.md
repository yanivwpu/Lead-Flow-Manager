# Disabled Shopify Agentic Commerce compatibility probe

The first milestone is a thin server-side UCP Catalog diagnostic adapter in the existing AI Brain Test Chat. `SHOPIFY_AGENTIC_PROBE_ENABLED` is false in source. No environment variable, browser request, administrator role or model response enables it. The existing diagnostics panel contains one collapsed read-only check; no new dashboard or integration is created.

The fixed endpoint is the connected installation's canonical `https://{shop}.myshopify.com/api/ucp/mcp`. The adapter reads `/.well-known/ucp`, lists negotiated MCP tools and runs only `search_catalog`. It does not call discovered endpoints or tool names. `lookup_catalog` and `get_product` are reported as advertised schema support only; cart, checkout and order capabilities are never executed. An advertised checkout capability is explicitly distinguished from verified execution support.

The server resolves the current owner, installation, OAuth credential, source and saved Test Chat selection. Independent server pins bind the operator/workspace, owner email and exact shop. Missing pins deny access. The existing Brain/admin transport and Shopping entitlement still apply. Every product and variant pair returned by MCP must exist in this tenant's owned source, with fresh Admin identity/price/inventory checks. Unknown products fail closed as unavailable, including legitimate products not yet synchronized; this conservative membership policy is not evidence that Shopify lacks those products. No global catalog, fallback merchant or custom-domain redirect is used.

Authentication uses an explicitly configured HTTPS UCP agent-profile URL and no API key, Storefront token, Admin token, cookies or buyer identity on MCP requests. The existing installed Admin credential is used only through the existing Admin provider. A missing agent profile is configuration-required. HTTP 401/403 identifies an authentication or store-access requirement, not proof of which one failed. Token-based buyer access, actual buyer-IP handling and profile hosting are outside this milestone; no IP is invented or forwarded. Existing OAuth, consent and credentials are unchanged.

The same bounded product-title query runs through the working tenant-scoped catalog search and the standard MCP search (five products each). Diagnostics include product counts and overlap only. Standard amounts are integer minor units; Admin prices are decimal major units. Currency-aware exact conversion handles zero-, two- and three-decimal currencies without floating-point equality. Fresh Admin availability is compared with the catalog availability signal. Exact inventory quantities remain an existing inventory-verification responsibility. This probe does not replace that verifier or authorize purchasing from catalog results.

Supported, unsupported, unavailable and configuration-required statuses have fixed sanitized reasons. Empty results, schema errors, provider errors and missing configuration do not become eligibility claims. Password redirects are detected with redirects disabled; other redirects and non-JSON responses remain unavailable. A password barrier does not prove permanent store ineligibility. No password submission, cookie bypass, store configuration or publication changes occur. Responses have byte/time limits and no retries; per-workspace concurrency and cooldown are bounded. Installation, owner, session, entitlement and catalog bindings are rechecked before returning results. No provider body, URL, token or transcript is rendered or logged.

Cart mutations, checkout initiation/navigation, orders, payments and outbound customer messaging are absent. No migrations, journal writes, claims, grants or startup jobs are added. PR #204 remains separate and unmerged. The original consumed cart request, shop-wide unique dispatch index and false custom-cart gate are unchanged; a regression preserves the real journal row and index while the read-only probe runs.

Tests use synthetic tenants, injected HTTP responses and disposable PostgreSQL/PGlite databases. They establish adapter behavior, not this connected store's live eligibility. Live store verification remains unavailable in this disabled, undeployed milestone. A later separately reviewed activation and authorized live read is needed to establish actual endpoint availability, negotiated schemas, password impact and discovery parity. No store configuration should be changed to make this test pass.

CI runs focused probe tests and the existing catalog, Shopping, authorization, UI and build checks. The CodeQL job runs JavaScript/TypeScript security-extended queries and retains SARIF as a review artifact without altering repository code-scanning configuration.

References: [Shopify Agents](https://shopify.dev/docs/agents), [Storefront Catalog MCP](https://shopify.dev/docs/agents/catalog/storefront-catalog), [UCP catalog MCP binding](https://ucp.dev/specification/shopping/catalog/mcp/). These document `/api/ucp/mcp`, `search_catalog`, `lookup_catalog`, `get_product`, the agent-profile requirement and the UCP catalog response envelope. Legacy `/api/mcp` search tools are not used.
